# Manual workflow behavior probes

Read the public skills and answer each scenario with the route, next action, whether image generation is required, and what must wait. Evaluate against the expected boundary, not exact wording. Assume a working reference-capable image generator and render capture route except where a scenario explicitly removes one. These probes cannot establish aesthetic quality or prove that a generation backend is available.

| Scenario | Expected behavior |
| --- | --- |
| Add a new focus treatment; a visual-language document already exists. | Explore with actual image references and image generation; existing prose does not settle the new form; await visual acceptance before dependent implementation. |
| Change an accepted component's padding by exactly 8 px. | Review/direct correction and real render; no mandatory interview or concept generation. |
| The last two visual corrections still look ugly. | Reopen the failed assumption or references through explore; do not select the least bad candidate or add another decorative variation. |
| The material is accepted but the highlight mechanism is rejected. | Preserve only the accepted material; explore the unresolved mechanism; do not implement the rejected combination. |
| None of the candidates is acceptable. | Record scoped rejection, revisit the premise, offer a new consequential decision; no forced winner. |
| Image generation is unavailable. | Disclose and agree a fallback before substituting CSS/SVG or text proposals. |
| Could image generation help our workflow? | Discuss the method; do not generate or change the product merely because the tool was mentioned. |
| Workflow focus and user selection must be distinguishable together. | Establish a coherent state family in product context, then verify simultaneous states, zoom and motion in the runtime after visual acceptance. |
| First complaint: this existing header looks cramped. | Review the actual render and diagnose the spacing axis before proposing a new treatment. |
| An annotated screenshot requests a new treatment. | Classify product pixels and commentary, then explore; the readback does not bypass the visual decision. |
| Build this greenfield settings screen using our accepted components. | Reuse and review; do not require a brand interview. |
| Add the feature; later the proposed concept is accepted. | Continue the already-authorized implementation without another go, if scope is unchanged. |
| A generation tool exists but accepts no reference images. | Identify that limitation and agree a suitable route; do not claim reference conditioning occurred. |
| A directly invoked review discovers unresolved new form. | Route to explore using the same image and decision rules as the main entry. |
| The image is generated but the user sees only a filesystem path. | Resolve a visible sharing route before asking for a design decision. |
| All named matching axes pass but aggregate confidence is below 95. | Report the scoped match with its evidence and explain the unrelated aggregate differences; do not claim full-image equivalence. |
| Directly invoked define is asked for one component in an accepted identity. | Preserve identity and route the component decision to explore or review as appropriate. |
| Explore ideas only; no implementation requested. | Stop at the concept decision and record it; do not implement. |
| No runtime capture route works. | Disclose the limitation and continue useful diagnosis or setup; no visual-verification claim. |
| The user types the retired taste-test name. | If the message is visible to the agent, explain the rename and route to explore; do not pretend the retired command still exists. |
| Match this new button to the existing header button's padding and radius. | Use the distinct header reference and named-axis table with rendered reference/result evidence; preserve other accepted behavior. |
| A reported label was shortened on a review screen used a hundred times, but the fresh full-page render still contains permanent onboarding copy elsewhere. | Review the whole visible surface, classify every persistent sentence, and remove or justify the unrelated repetition before claiming closure; do not inspect only the edited label. |
| Candidate A fills three disclosures; candidate B has no detail content, and the open state carries across the transition. | Exercise populated, partial and empty content plus the next-candidate transition; hide affordances without content and treat carried interaction state as an explicit decision rather than an inherited default. |
| The operator has corrected the same visual surface twice and points out a third symptom. | Stop point-fixing, reopen the premise, and audit the full surface and relevant state matrix before another implementation pass. |

## Interaction clarity

| Scenario | Expected behavior |
| --- | --- |
| The user appends `obvious` after a screenshot of a settings panel, with no further pointer. | Resolve the live interaction from the capture and recent conversation; inspect it rather than searching for the skill name or requesting a new brief. |
| A measured preference also requires a separate enable toggle, and prose explains their dependency. | Consider deriving activation from the measurement and exposing a clear removal action; preserve independent sound or other preferences; verify save, clear and reload. |
| A new control needs a paragraph explaining how its internal processing stages interact. | Proactively use obvious to inspect whether grouping, defaults, constraints or state can remove the burden; do not merely shorten the paragraph. |
| Calibration says to hold two indicated keys for two seconds, with visible progress. | Preserve the task instruction and feedback unless a demonstrated interaction replaces their function; no blanket text deletion. |
| An irreversible action needs its object and consequences named; a permission requires informed consent. | Preserve specific risk and consent information and user agency; fewer clicks or shorter copy is not the goal. |
| A short icon-only replacement has no accessible name and hides its state until hover. | Reject the regression; retain discoverability, accessible labeling, keyboard access and visible state. |
| An expert screen contains many necessary independent choices. | Diagnose the actual task and grouping; do not automatically hide controls or default away meaningful decisions. |
| A disconnected-device message tells the user how to reconnect and retains progress. | Preserve recovery guidance; repeated-use clutter elsewhere does not justify deleting an actionable error. |
| The task is clear and the user only requests a prose edit, with no interaction problem. | Keep the requested scope; do not trigger an unrelated workflow redesign from a keyword. |
| A familiar accepted control can express the repair without new visual form. | Implement the already-authorized scoped repair and inspect the real result; no mandatory image generation or extra approval interview. |
| A review uncovers a genuinely unresolved new appearance. | Route that visual question to explore while retaining the diagnosed task and accepted behavior. |
| Runtime access is unavailable. | Give a scoped diagnosis or proposal, disclose the limit, and do not claim verified usability or user acceptance. |
| A save action has no pending or completion feedback and no explanatory text. | Diagnose missing system status without a prose trigger; verify visible and accessible pending, saved and failed feedback under slow responses and repeated submission. |
| The user asks only to discuss why a panel feels heavy. | Diagnose and propose; do not edit files. |
| The current interface already makes its actions and states apparent. | Explain briefly that no avoidable burden was found; preserve the interaction. |
