# Image generation across hosts

The workflow requires a real image-generation capability; naming a tool in prose does not make one available. This plugin does not provide a model server or credentials.

1. Inspect the current host's tool and skill catalog. Prefer its native image-generation tool when present and authorized. Otherwise read the installed image-generation skill and verify its documented executable or connected service. A broken MCP entry does not prove that an independently installed CLI is unavailable.
2. Check the selected route supports the intended reference-image operation. Confirm the actual provider/model and quality settings where the route exposes them; aliases and cheap preview defaults are not evidence of the requested model or output quality. Honor existing user choices. Do not downgrade models or omit reference inputs silently.
3. Follow that route's credential and permission rules. Do not invent flags, expose credentials, install another backend or create account state merely to satisfy this workflow. If the required capability is missing, explain precisely what is missing and resolve the route with the user before producing substitute concepts.
4. Inspect reference files before use. Provide their roles, visual invariants, open decision, product context and required state family in the prompt. If the route accepts fewer references than needed, agree how to preserve the essential evidence rather than pretending all inputs were supplied.
5. Verify the returned image can be opened and record the actual artifact. Inspect it before presenting. Preserve accepted artifacts in a durable project location or shared artifact; temporary files are not permanent image anchors. Unless the project has a convention or the user chooses otherwise, store accepted anchors in an assets directory alongside the project's canonical visual-language document and use relative links. For a new project, use docs/visual-language.md if a docs directory exists, otherwise visual-language.md at the project root. During exploration, preserve provisional tool outputs; copy selected anchors into the durable location when recording the accepted decision.

Before asking for a design decision, confirm the proposals are visibly rendered in the conversation or an accessible shared artifact. A local path alone is insufficient. If display is unavailable, disclose that constraint and resolve a viewing route before asking the user to choose.

Claude Code can use a configured image-generation MCP or an installed generation skill/CLI. Codex can use its native image tool or a configured route. Never assume that capabilities available in one host also exist in another. Loading the same SKILL.md on both hosts verifies instruction portability, not backend availability or visual quality.
