# Artifact storage

Resolve destination, audience and retention before creating output. A code checkout is the audit's input, not its default output directory. Follow an explicitly agreed destination and the host's canonical knowledge-storage rules; do not create a project report, hidden project directory or permanent archive merely because an audit ran.

- **Quick checks:** return the verdict inline; create no report files.
- **Temporary work:** use host scratch space or a uniquely owned temporary directory. Remove only this run's temporary files before handoff, after delivering or preserving anything still needed.
- **Retained run state:** keep checklists, evidence and comparison baselines together under `${LAICLUSE_HOME:-$HOME/.laicluse}/drydry/audits/<repository-key>/<run-id>/`. This is the default for audit and parity runs, without an extra retention question. An explicitly disposable audit delivers its complete checklist and findings inline, preferably without creating report files; any necessary scratch files are removed after delivery. Use a stable repository identity, such as remote host/owner/repository or a hash of the canonical repository or non-Git scope root. Normalize equivalent remote URL forms to the same identity; linked worktrees share the canonical repository identity. Do not group unrelated repositories by basename or identify one repository by an ephemeral worktree path. Allocate a distinct run directory with an exclusive directory-creation operation, such as the host’s `mktemp -d` equivalent; timestamps alone are not collision-safe. A named prior baseline takes precedence. Otherwise inspect retained run metadata within this repository’s state directory and select the latest completed baseline with the same audit kind, method and scope. With no match, establish a new baseline. Preserve the previous baseline when writing a comparison run.
- **Framework review cache:** resolve one cache directory under `${LAICLUSE_HOME:-$HOME/.laicluse}/drydry/cache/<repository-key>/upstream/`, using the same repository identity as audit state. Read and write the same version-keyed files there; preserve the existing lock-file hash invalidation rules.
- **Durable knowledge or a requested report:** use the appropriate registered vault, knowledge store or agreed documentation location. A report belongs in the repository only when it is intended project content. Transfer and verify the retained result before removing temporary copies, and link it from its owning context. A path in the conversation alone is not durable discovery.

If stable repository or scope identity cannot be established, do not create a baseline under a guessed key; deliver the full result inline and disclose that limitation. If the intended destination is not writable under the host’s current permissions, use its normal permission route when available. If persistence remains unavailable, deliver the full result inline and state that no retained baseline was created; never fall back to writing in the checkout.

Record the repository, audit kind, scope, source revision, method, timestamps, completion state, retention purpose and destination in the run's findings or report. Keep the finalized checklist with those findings for the same lifetime. Do not copy personal context or another project's content into shared output. Respect existing secret-storage rules; this storage contract does not authorize retaining secrets.

Resolve one `learnings_dir` for both research output and seed lookup: the caller's agreed override, otherwise `${LAICLUSE_HOME:-$HOME/.laicluse}/drydry/learnings/`. It holds reusable technique proposals, not project-specific audit reports. Resolve it from explicit caller input or an existing host instruction; a per-call override is not silently made permanent. Use that same resolved directory for creation, prior-date lookup, writing and later checklist consumption. Report the directory so a later caller can supply the same override or follow the existing host instruction. Research output filenames must be unique even for concurrent calls on the same topic; allocate them exclusively rather than overwriting a date/topic filename. Derive the default research window from the latest completed proposal for the same topic, or the broad topic when none was specified. Do not mix it with a project-local `.drydry` directory. An existing agreed override remains valid; a new destination inside a checkout needs an intended project-content purpose.

Report the result and its destination, and identify any state deliberately retained for a later run. Do not invent a second copy or a cleanup announcement in the audited project.
